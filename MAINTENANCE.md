# Serph91P Arctic Fuse 3 maintenance

The maintained fork keeps `skin.arctic.fuse.3`, original dependencies and
jurialmunkey attribution/license. `omega` is the publication branch. The fork
adds a numeric package revision (first: 3.4.18.1), so Kodi can select it above
the corresponding upstream version. Select **repository.serph91p** as the source;
original dependency repositories and their identities/feeds are not rewritten.

## Local patch

The current solution from upstream PR436 is ported onto upstream omega

video browsing/player contexts, preserves music artist/TV/fallback branches,

## Daily updates

`Daily upstream check` runs once at 05:23 UTC on the default branch. Its first
operation compares the upstream ref with `.maintenance/upstream.json`. An
unchanged revision causes no package build, branch, dispatch, issue write or PR.
A new revision is merged into a fresh `maintenance/upstream-<sha>` branch,
retaining fork commits, bumping the numeric version and running the real tests.
Only a passing candidate is pushed, without force. `workflow_dispatch` runs the
same immutable package validation for that candidate. A single `upstream-update`
issue links the comparison and records the checked SHA, so the same pending or
conflicting revision is not rebuilt every day. Conflicts are shown explicitly;
no reset, auto-resolution of skin changes, merge or publication takes place.

GitHub currently forbids Actions from creating PRs in this repository. Therefore
the issue links the native compare/open-PR page, rather than adding a PAT or
loosening repository permissions. Review/merge is an owner action. Manually
rerun an intentionally retried revision by removing that revision marker from
the tracking issue after resolving the problem. On subsequent upstream changes
the tracker updates the same open issue. Merge a successful candidate back to
omega only after review and explicit merge/publication approval.

## Packaging and approval order

`Add-on Validations` executes title/merge regression tests and calls the existing
SHA-pinned repository.serph91p reusable packager with an explicit runtime allowlist.
PR/candidate artifacts are test-only; only successful omega push/manual runs
may notify the existing immutable publication pipeline. Package bytes, version,
SHA, run, workflow and evidence identity remain bound together. No leaf-feed
mirroring, empty catalog rows or manual ZIP publication bypass is introduced.

Catalog bootstrap is allowed only until the first real validated skin package
has been published; then remove that single pending flag. Merge target policy
before source publication, and verify the downloaded feed/package against the
source evidence. The notifier requires the owner's existing dispatch credential
in `REPO_DISPATCH_TOKEN`; no new token is generated by these workflows.

Rollback is selection/reinstallation of the previously published skin package
or a reviewed Git revert with a new monotonically increasing package version.
Never overwrite a released version with different bytes. Max controls skin
reload/switching; validation must not play videos or restart Kodi.

GitHub documentation: https://docs.github.com/actions/using-workflows/triggering-a-workflow
(GITHUB_TOKEN push suppression and workflow_dispatch exception).
